# Дневник достижений

Личное веб-приложение на одного человека — цифровая версия бумажного «Дневника достижений».
Открывается с телефона и компьютера, ставится на домашний экран (PWA), все записи лежат в одном
файле SQLite на вашем сервере. Никаких сторонних облаков, аналитики, шрифтов и CDN.

- **Сегодня** — форма из семи полей, как на бумаге. Обязательно только «Достижение дня».
  Категорий можно отметить несколько или ни одной.
  Черновик сохраняется на устройстве при каждом изменении.
- **История** — лента от новых к старым, календарь, поиск по тексту, фильтр по категории.
- **Вспомни хорошее** — случайное достижение из прошлого и кнопка «Ещё одно».
- **Настройки** — тема, экспорт (JSON / Markdown / CSV), импорт, смена пароля.

Серий, счётчиков пропусков, напоминаний и геймификации нет намеренно.

## Стек

| Часть    | Что используется |
|----------|------------------|
| Сервер   | Node.js 22, TypeScript, Fastify, better-sqlite3, argon2 |
| Клиент   | Vite, Preact, TypeScript, свой service worker |
| Деплой   | один Docker-образ, docker-compose, Caddy (HTTPS) |

```
server/src   API, авторизация, экспорт/импорт, бэкапы
server/test  тесты API (vitest)
shared       типы и константы, общие для сервера и клиента
web          фронтенд (PWA)
```

## Запуск локально

Нужен Node.js 20+.

```bash
npm install
```

**Режим разработки** — два терминала:

```bash
DIARY_PASSWORD='пароль-от-8-символов' COOKIE_SECURE=false npm run dev:server
```

```bash
npm run dev:web
```

Откройте http://localhost:5173. Vite проксирует `/api` на сервер (порт 3000).
Service worker в режиме разработки не регистрируется.

**Как в продакшене** (собранный фронтенд отдаёт сам сервер):

```bash
npm run build
```

```bash
DIARY_PASSWORD='пароль-от-8-символов' npm start
```

Откройте http://localhost:3000. База появится в `./data/diary.sqlite`, бэкапы — в `./backups`.

**Тесты и проверка типов:**

```bash
npm test
```

```bash
npm run typecheck
```

## Деплой на VPS

Понадобятся: VPS с Docker и плагином compose, домен с A-записью на IP сервера, открытые порты 80 и 443.

1. Скопируйте репозиторий на сервер и перейдите в его каталог.

2. Создайте `.env`:

   ```bash
   cp .env.example .env
   ```

   Впишите в него `DIARY_DOMAIN` (ваш домен) и `DIARY_PASSWORD` (не короче 8 символов).

3. Создайте каталоги для данных и отдайте их пользователю, под которым работает контейнер (uid 1000):

   ```bash
   mkdir -p data backups && sudo chown -R 1000:1000 data backups
   ```

4. Запустите:

   ```bash
   docker compose up -d --build
   ```

   Caddy сам получит сертификат Let's Encrypt. Через минуту дневник откроется по `https://ваш-домен`.

5. Уберите `DIARY_PASSWORD` из `.env`: пароль уже сохранён в базе в виде хеша argon2id,
   и переменная больше не читается. Дальше пароль меняется в «Настройках».

**Обновление:**

```bash
git pull && docker compose up -d --build
```

**Логи:**

```bash
docker compose logs -f app
```

**Забыли пароль.** Впишите в `.env` новый `DIARY_PASSWORD` и `DIARY_PASSWORD_RESET=1`,
выполните `docker compose up -d`, затем удалите обе строки и выполните команду ещё раз.
Все сессии при сбросе завершаются.

**Установка на телефон.** Откройте сайт в браузере: iOS Safari — «Поделиться» → «На экран „Домой“»;
Android Chrome — меню → «Установить приложение».

### nginx вместо Caddy

Уберите сервис `caddy` из compose, опубликуйте приложение только на localhost
(`ports: ["127.0.0.1:3000:3000"]`) и проксируйте с nginx, у которого уже настроен HTTPS:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 50m;   # импорт больших JSON
}
```

Заголовок `Host` должен передаваться без изменений: по нему сервер проверяет `Origin` запросов.

## Бэкапы

Сервер сам делает копию базы раз в сутки (и при запуске, если копии за сегодня ещё нет) через
SQLite Online Backup API — копия получается целостной даже при работающем приложении.
Файлы называются `backups/diary-ГГГГ-ММ-ДД.sqlite` (дата по UTC), хранятся последние 14.

Копии лежат на том же сервере, поэтому забирайте их к себе. С вашего компьютера:

```bash
rsync -av user@ваш-сервер:/путь/к/achievement-diary/backups/ ~/diary-backups/
```

Или один файл через scp:

```bash
scp user@ваш-сервер:/путь/к/achievement-diary/backups/diary-2026-11-16.sqlite ~/diary-backups/
```

Чтобы это происходило само, добавьте rsync в cron на своём компьютере (`crontab -e`):

```
30 12 * * * rsync -a user@ваш-сервер:/путь/к/achievement-diary/backups/ ~/diary-backups/
```

rsync без `--delete` не удаляет у вас старые копии, так что дома история будет длиннее 14 дней.

**Восстановление из копии:**

```bash
docker compose stop app
```

```bash
cp backups/diary-2026-11-16.sqlite data/diary.sqlite && rm -f data/diary.sqlite-wal data/diary.sqlite-shm
```

```bash
docker compose start app
```

Второй, независимый способ — JSON-экспорт из «Настроек»: его можно импортировать в чистую установку.

## Безопасность

- Один пользователь. Пароль хранится только как хеш argon2id.
- Сессия — случайный токен в cookie `__Host-diary_session` (`HttpOnly`, `Secure`, `SameSite=Strict`),
  в базе лежит только SHA-256 от токена. Срок — 30 дней (`SESSION_DAYS`).
- Все маршруты `/api/*`, кроме `/api/login` и `/api/health`, требуют сессию.
- Вход ограничен: 10 попыток за 15 минут с одного IP (`LOGIN_RATE_MAX`).
- Изменяющие запросы с чужим `Origin` отклоняются.
- Заголовки: строгий CSP (`default-src 'self'`, без inline-скриптов и стилей), `X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy: no-referrer`, HSTS, `Permissions-Policy`, `X-Robots-Tag: noindex`.
- Смена пароля завершает сессии на остальных устройствах.

Что стоит знать:

- **База на диске не зашифрована.** Кто имеет root-доступ к VPS или к файлам бэкапов, может прочитать записи.
  Если это важно — включите шифрование диска и храните домашние копии на зашифрованном носителе.
- **На устройстве хранится копия записей** (IndexedDB) для просмотра без сети, а черновики — в localStorage.
  Кнопка «Выйти» стирает и то, и другое. Истёкшая сессия сама по себе копию не стирает.

## Офлайн

Service worker кэширует только оболочку приложения (HTML, JS, CSS, иконки); запросы к API он не трогает.
После входа приложение сохраняет копию записей на устройстве, поэтому без сети работают история,
поиск, календарь, просмотр записей и «Вспомни хорошее».

Писать без сети тоже можно: текст сохраняется как черновик на устройстве. На сервер он попадёт,
когда вы нажмёте «Сохранить» при появившейся связи, — автоматической отправки в фоне нет.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DIARY_PASSWORD` | — | пароль для первого запуска или сброса |
| `DIARY_PASSWORD_RESET` | `0` | `1` — перезаписать пароль значением `DIARY_PASSWORD` |
| `PORT`, `HOST` | `3000`, `0.0.0.0` | адрес сервера |
| `DATA_DIR` / `DB_PATH` | `./data` / `$DATA_DIR/diary.sqlite` | где лежит база |
| `BACKUP_DIR`, `BACKUP_KEEP` | `./backups`, `14` | каталог и число хранимых копий |
| `COOKIE_SECURE` | `true` | `false` — только для локальной разработки по http |
| `SESSION_DAYS` | `30` | срок жизни сессии |
| `LOGIN_RATE_MAX` | `10` | попыток входа за 15 минут с одного IP |
| `STATIC_DIR` | `dist/web` | собранный фронтенд |
| `LOG` | `true` | журнал запросов (cookie в него не попадают) |

## API

Все ответы — JSON. Ошибки: `{ "error": "текст" }`.

| Метод и путь | Описание |
|---|---|
| `POST /api/login` | `{ password }` → ставит cookie сессии |
| `POST /api/logout` | завершает сессию |
| `GET /api/session` | 200, если сессия действует, иначе 401 |
| `POST /api/password` | `{ current, next }` — смена пароля |
| `GET /api/entries` | параметры `q`, `category`, `from`, `to`, `limit` (≤100), `offset` → `{ items, total, limit, offset }`, от новых к старым |
| `GET /api/entries/:date` | запись на дату или 404 |
| `PUT /api/entries/:date` | создать (201) или заменить (200) запись; обязательно поле `achievement`; `categories` — массив названий |
| `DELETE /api/entries/:date` | удалить запись |
| `GET /api/dates` | даты всех записей (для календаря) |
| `GET /api/stats` | `{ total, first_date }` |
| `GET /api/random` | случайная запись; `?exclude=ГГГГ-ММ-ДД` — кроме указанной |
| `GET /api/export?format=json\|md\|csv` | файл экспорта |
| `POST /api/import` | `{ entries, resolutions?, onConflict? }`; `?dryRun=1` — только сводка и список конфликтов |
| `GET /api/health` | проверка живости, без авторизации |

Импорт сливает записи по дате. Если запись на дату уже есть и отличается, нужно решение:
`resolutions: { "2026-01-02": "keep" | "replace" }` или общее `onConflict`. Без решения сервер
отвечает 409 со списком конфликтов и ничего не меняет. Файл с ошибкой отклоняется целиком.
Принимаются и старые файлы, где у записи одна категория в поле `category`.

Пример с curl:

```bash
curl -c jar -H 'Content-Type: application/json' -d '{"password":"..."}' https://ваш-домен/api/login
```

```bash
curl -b jar -o diary.json 'https://ваш-домен/api/export?format=json'
```
